[size=5][b]FeverLink3 Multiplayer - early test build 0.2.0-test1[/b][/size]

[quote][b]Experimental, and not a playable multiplayer game yet.[/b] This first test build has one job: to find out whether two players can reach each other through Steam. It adds a window to the game with a [b]Steam connection test[/b]. Hosting and joining a game over that connection come in the next test build, and building together after that. What is verified and what is not is listed below. If you would like to help test, you are very welcome.[/quote]

[line]

[size=4][b]What it is[/b][/size]

FeverLink3 aims to let several players build in the same Transport Fever 3 world at the same time, each in their own copy of the game.

[list]
[*][b]Same commands, same step.[/b] Every action a player takes is sent to all games and applied at the same simulation step on every one of them, so the worlds stay identical without sending the world around.
[*][b]One host.[/b] The host decides who may do what. Friends join with a short code. The games compare checksums, and a lasting difference is repaired by loading the host's savegame everywhere.
[*][b]Encrypted.[/b] Everything between the games is encrypted and authenticated with a key derived from the join code.
[*][b]Connected through Steam.[/b] The games reach each other through Steam's peer-to-peer networking, so a friend only needs the join code and, by design, nothing has to be set up. Whether that holds on real home connections is what this test build is for.
[/list]

It is a fresh implementation in Rust and Lua, with the source on GitHub under the PolyForm Noncommercial License (free for noncommercial use). It stands on two earlier projects that proved the approach, credited at the bottom. It is [b]not official[/b]: it is not made, endorsed or supported by Urban Games or Paradox Interactive.

[size=4][b]What this test build does, and what it does not[/b][/size]

[list]
[*][b]Does:[/b] adds a button called [b]FeverLink3[/b] to the bar at the bottom of the screen. It opens a window with a [b]Steam connection test[/b]: two players exchange Steam IDs, test the connection to each other and read the result (connected or not, how many answers, the round-trip time, and whether Steam used a direct route or its own relay).
[*][b]Does not (yet):[/b] host or join a game. The window's [b]Host a game[/b] button answers that hosting over Steam is not finished in this build yet. Those come in the next test build.
[/list]

[size=4][b]Requirements[/b][/size]

[list]
[*]Transport Fever 3 on Steam, game build [b]40420[/b] (shown at the bottom right of the main menu). Each player needs their own copy, started through Steam, and the same build as the other player.
[*]Windows 10 or 11, 64-bit. Steam running and logged in.

[size=4][b]Installation[/b][/size]

The zip holds a testing installer, the native module (winhttp.dll) and the mod. The installer is a testing tool: the plan is that the mod reaches players from the game's own Mod Hub and from Nexus Mods like any other mod, with the native module as a separate download for now.

[list=1]
[*]Close Transport Fever 3.
[*]Download the zip, unzip it anywhere (Extract All) and double-click feverlink3.exe; a menu opens, type 1 and press Enter to install. From a terminal opened in that folder the same is:
[code]feverlink3 install[/code]
Windows SmartScreen may say "Windows protected your PC" the first time, because the program is not code-signed yet: click More info, then Run anyway. Add --dry-run to see what it would do first.
[*]It prints one line per item (the mod, steam_appid.txt, winhttp.dll, feverlink3_path.txt), each marked DONE, SKIP or FAILED with the reason. If a line says the Steam user folder does not exist, start the game once, close it and run the command again.
[*]Start Transport Fever 3 from Steam. When you start a game, open the mod list on the settings page, find FeverLink3 Multiplayer and activate it. The [b]FeverLink3[/b] button appears in the bar at the bottom of the screen.
[/list]

Without the installer: copy winhttp.dll into the Transport Fever 3 game folder and the folder mod\feverlink3_1 into (your Steam folder)\userdata\(your Steam user id)\3493540\local\mods\ . That is what the installer does for the in-game window (the other two files it writes are not used by the in-game window). This route has not been tested separately; if the button does not appear, use the installer and tell us.

[size=4][b]Running the connection test[/b][/size]

Two testers, both with the game running through Steam:

[list=1]
[*]Click [b]FeverLink3[/b] in the bottom bar. Under Steam connection test the window shows [b]Your Steam ID[/b]. Send it to the other tester, who sends you theirs. A Steam ID identifies your Steam account, so share it only with the person you test with.
[*]Paste the other tester's Steam ID into the field "paste the other player's Steam ID" and press [b]Test the connection[/b].
[*]Within about 20 seconds the window shows a line like "Test: connected, answers 6, last round trip 40 ms, direct" (or "through a Steam relay"). The other tester's window shows how many pings it received.
[*]Try both directions, and send the result lines, your two countries and whether anything failed to the maintainer (Discord azalshehri, or GitHub issues).
[/list]

If the window says "The FeverLink3 module is not running", close the game, run feverlink3 install again and start the game from Steam. The full guide is in the zip (HOW-TO-PLAY.txt) and here: [url=https://github.com/AZalshehri7/FeverLink3/blob/main/docs/PLAYING.md]Playing FeverLink3[/url]

[size=4][b]The file winhttp.dll, safety and antivirus[/b][/size]

The mod ships one native file, winhttp.dll. The game imports that name, so Windows loads it from the game folder when the game starts. It passes the game's 14 WinHTTP functions to the real Windows file unchanged and, inside the game, runs the Steam connection test (and, in later test builds, the multiplayer session) on one thread. It does not inject into other programs, does not start with Windows, needs no administrator rights, sends no telemetry and does not download or run programs. By default it installs no hooks into the game: the hook code is switched off unless a developer sets environment variables, and it has never run in the real game. The source is public, and the page below lists exactly what it does and does not do, which files it creates, how to check the hash, and how to report a false positive to Microsoft, Kaspersky, ESET and others.

The same loading technique is used by malware, and the file is [b]not code-signed yet[/b], so some antivirus programs may flag it. Code signing is planned.

[url=https://github.com/AZalshehri7/FeverLink3/blob/main/docs/SECURITY_FOR_USERS.md]What is in winhttp.dll, and how to check it[/url]

[size=4][b]What goes over the network[/b][/size]

[list]
[*]Between the players: Steam's peer-to-peer networking through the Steam library the game already runs. Steam may relay the traffic through its own servers. No server of the project is involved, and the host does not open an inbound TCP port in normal use.
[*]Nothing else: no analytics, no update check, no advertising, no account, no web requests of its own. The mod needs the network for one thing only: connecting the players.
[*]What the other tester's game receives in the connection test: short ping messages sent from your Steam account (their window only counts them). In later builds, other players will see your display name (it starts as your Windows user name; change it in the window), your game actions and chat; a host will also send the world.
[*]Session traffic is encrypted and authenticated by the mod itself (AES-256-GCM, key derived from the join code).
[/list]

[size=4][b]Uninstall[/b][/size]

Close the game and run [b]feverlink3 uninstall[/b] (add --dry-run to see the plan). It removes the mod, our winhttp.dll, feverlink3_path.txt and, if it holds exactly the game's app id, steam_appid.txt. It never touches another mod's winhttp.dll. Optional clean-up: delete %LOCALAPPDATA%\FeverLink3 (logs and session files), %TEMP%\feverlink3, and files named feverlink3-resync-*.sav in your save folder.

[size=4][b]Known issues[/b][/size]

[list]
[*]Not a finished multiplayer game: this build tests the Steam connection only, and everything under "Not verified yet" above.
[*]The native hooks are switched off (only a developer can turn them on) and have never run in the real game, so construction commands are not held back to the same moment on every game yet.
[*]Only game build 40420 is known. If a game update changes the web functions the game imports, the game may fail to start while winhttp.dll is installed; uninstalling fixes it.
[*]Not code-signed: SmartScreen and some antivirus programs warn. Windows 11 Smart App Control in its "On" setting may block the unsigned DLL; this has not been tested.
[*]Another mod's winhttp.dll conflicts with ours; the installer refuses to overwrite it.
[*]The window is English only. A bug in the native module can crash the game (it aborts on an internal error).
[*]The installer's double-click menu has been tested on a fake PC and a fake Steam tree, not yet on a clean PC by someone else.
[/list]

[size=4][b]FAQ[/b][/size]

[spoiler]
[b]Does it work?[/b] Partly; see the status above. This build tests the Steam connection; hosting and joining over Steam are the next test build, and playing together in two real games has not been verified yet.

[b]How do the players connect?[/b] Through Steam's peer-to-peer networking. By design nothing has to be set up. It is being tested: inside one game it is proven, between two different accounts it has not been tried yet.

[b]Is winhttp.dll safe? My antivirus flags it.[/b] See the security page above. Check the hash against the release notes, and report false positives; the page lists where.

[b]Windows says "Windows protected your PC".[/b] SmartScreen reacts to a new, unsigned program. More info, then Run anyway. It appears once for the installer.

[b]Is it official?[/b] No. It is an unofficial community project.

[b]Can I use it with MPFever?[/b] No; both use the winhttp.dll slot, and our installer will not overwrite another mod's file.

[b]Will it break my saves?[/b] The mod does nothing until you host or join. Later builds will make every game load the host's world and write files named feverlink3-resync-(number).sav into your save folder, so back up your saves first.

[b]Can I play on my own with it installed?[/b] Yes, by design: without a session the game plays as it always does.

[b]Which game version?[/b] Build 40420 for now. After a game update the module may need an update; if the game fails to start, run feverlink3 uninstall and tell us your build.

[b]Consoles, Mac, Linux, Epic or GOG?[/b] No. The native part is a Windows DLL and the installer finds the game through Steam.

[b]Will it be in the in-game Mod Hub or on the Steam Workshop?[/b] Transport Fever 3 has no Steam Workshop. The plan is to offer the mod in the game's own Mod Hub (which runs on mod.io) and here on Nexus Mods, with the native module as a separate download for now. Whether the Mod Hub accepts a mod that needs a separate native component is still being checked: its published rules allow only the official scripting API. Details: [url=https://github.com/AZalshehri7/FeverLink3/blob/main/docs/WORKSHOP.md]the publishing plan[/url].

[b]How is it different from MPFever?[/b] It is a separate, fresh implementation (Rust and Lua) built on the same idea; both projects are credited below. They cannot be installed together.

[b]How do I help or report a bug?[/b] Discord azalshehri, or [url=https://github.com/AZalshehri7/FeverLink3/issues]GitHub issues[/url]. Please attach %LOCALAPPDATA%\FeverLink3\native.log and live\mod.log.
[/spoiler]
