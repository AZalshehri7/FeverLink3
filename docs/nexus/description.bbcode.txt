[size=5][b]FeverLink3 Multiplayer - early test build 0.2.0-test1[/b][/size]

[quote][b]Experimental. Please read this first.[/b] This is the first public test of an open-source multiplayer mod. It is [b]not yet a playable multiplayer game[/b]: the in-game window works and a session can be hosted from it, but building together between two real games has not been verified yet. The full list is below. If you want a finished co-op experience, wait for a later version. If you would like to help test, you are very welcome.[/quote]

[line]

[size=4][b]What it is[/b][/size]

FeverLink3 aims to let several players build in the same Transport Fever 3 world at the same time, each in their own copy of the game.

[list]
[*][b]Same commands, same step.[/b] Every action a player takes is sent to all games and applied at the same simulation step on every one of them, so the worlds stay identical without sending the world around.
[*][b]One host.[/b] The host decides who may do what. Friends join with a short code. The games compare checksums, and a lasting difference is repaired by loading the host's savegame everywhere.
[*][b]Encrypted.[/b] Everything between the games is encrypted and authenticated with a key derived from the join code.
[*][b]Connected through Steam.[/b] The games reach each other through Steam's peer-to-peer networking, and a relay server is being built as a fallback. The join code is all a friend needs. This part is still being tested; see the status.
[/list]

It is a fresh implementation in Rust and Lua, MIT licensed, with the source on GitHub. It stands on two earlier projects that proved the approach, credited at the bottom. It is [b]not official[/b]: it is not made, endorsed or supported by Urban Games or Paradox Interactive.

[size=4][b]Requirements[/b][/size]

[list]
[*]Transport Fever 3 on Steam, game build [b]40420[/b] (shown at the bottom right of the main menu). Every player needs their own copy and the same build as the host.
[*]Windows 10 or 11, 64-bit. Steam running and logged in.
[*]No other mod is needed. It cannot be used together with MPFever or any mod that installs its own winhttp.dll.
[/list]

[size=4][b]Installation[/b][/size]

[list=1]
[*]Close Transport Fever 3.
[*]Download the zip and unzip it anywhere. Open a terminal in that folder (type cmd into the folder's address bar and press Enter) and run:
[code]feverlink3 install[/code]
Windows SmartScreen may say "Windows protected your PC" the first time, because the program is not code-signed yet: click More info, then Run anyway. Add --dry-run to see what it would do first.
[*]It prints one line per item (the mod, steam_appid.txt, winhttp.dll, feverlink3_path.txt), each marked DONE, SKIP or FAILED with the reason. If a line says the Steam user folder does not exist, start the game once, close it and run the command again.
[*]Start Transport Fever 3 from Steam. When you start a game, open the mod list on the settings page, find FeverLink3 Multiplayer and activate it. A button called [b]FeverLink3[/b] appears in the bar at the bottom of the screen.
[/list]

Without the installer: copy winhttp.dll into the Transport Fever 3 game folder and the folder mod\feverlink3_1 into (your Steam folder)\userdata\(your Steam user id)\3493540\local\mods\ . That is what the installer does for the in-game window (the other two files it writes are not used by the in-game window). This route has not been tested separately; if the button does not appear, use the installer and tell us.

[size=4][b]Using it[/b][/size]

[b]Host:[/b] click FeverLink3 in the bottom bar, check your name, click [b]Host a game[/b]. The window shows a join code: click into it, press Ctrl+A and Ctrl+C, and send it to your friends. Press [b]Start the session[/b]. [b]Sync everyone to my world[/b] appears once the session has started. [b]Stop hosting[/b] ends it.

[b]Join:[/b] start the game with the mod activated, click FeverLink3, paste the code into the field, press [b]Join[/b], and wait for the host to start the session. The host's world is meant to be sent to you then.

[b]Only join people you know:[/b] your game loads the host's world, and a Transport Fever savegame can carry game scripts, as a mod can. Treat the join code like a password for that session.

[b]Help test the connection:[/b] while you are not hosting or joined, the window has a Steam connection test. Two testers each send the other their Steam ID, paste it in, press [b]Test the connection[/b] and report the result line (for example "connected, answers 6, last round trip 40 ms, direct"). A Steam ID identifies your Steam account, so share it only with the person you test with.

The full guide is in the zip (HOW-TO-PLAY.txt) and here: [url=https://github.com/AZalshehri7/FeverLink3/blob/main/docs/PLAYING.md]Playing FeverLink3[/url]

[size=4][b]The file winhttp.dll, safety and antivirus[/b][/size]

The mod ships one native file, winhttp.dll. The game imports that name, so Windows loads it from the game folder when the game starts. It passes the game's 14 WinHTTP functions to the real Windows file unchanged and, inside the game, runs the multiplayer session on one thread. It does not inject into other programs, does not start with Windows, needs no administrator rights, sends no telemetry and does not download or run programs. This version installs no hooks into the game. The source is public, and the page below lists exactly what it does and does not do, which files it creates, how to check the hash, and how to report a false positive to Microsoft, Kaspersky, ESET and others.

The same loading technique is used by malware, and the file is [b]not code-signed yet[/b], so some antivirus programs may flag it. Code signing is planned.

[url=https://github.com/AZalshehri7/FeverLink3/blob/main/docs/SECURITY_FOR_USERS.md]What is in winhttp.dll, and how to check it[/url]

[size=4][b]What goes over the network[/b][/size]

[list]
[*]Between the players: Steam's peer-to-peer networking through the Steam library the game already runs. Steam may relay the traffic through its own servers. A relay server operated by the project is being built as a fallback. The host does not open an inbound TCP port in normal use.
[*]Nothing else: no analytics, no update check, no advertising, no account. The mod needs the network for one thing only: connecting the players.
[*]The other players see your display name (it starts as your Windows user name; change it in the window), your game actions and chat; a host also sends the world.
[*]Session traffic is encrypted and authenticated by the mod itself (AES-256-GCM, key derived from the join code).
[/list]

[size=4][b]Uninstall[/b][/size]

Close the game and run [b]feverlink3 uninstall[/b] (add --dry-run to see the plan). It removes the mod, our winhttp.dll, feverlink3_path.txt and, if it holds exactly the game's app id, steam_appid.txt. It never touches another mod's winhttp.dll. Optional clean-up: delete %LOCALAPPDATA%\FeverLink3 (logs and session files), %TEMP%\feverlink3, and files named feverlink3-resync-*.sav in your save folder.

[size=4][b]Known issues[/b][/size]

[list]
[*]Not a finished multiplayer game: everything under "Not verified yet" above.
[*]The native hooks are not enabled, so construction commands are not held back to the same moment on every game yet.
[*]Only game build 40420 is known. If a game update changes the web functions the game imports, the game may fail to start while winhttp.dll is installed; uninstalling fixes it.
[*]Not code-signed: SmartScreen and some antivirus programs warn. Windows 11 Smart App Control in its "On" setting may block the unsigned DLL; this has not been tested.
[*]Another mod's winhttp.dll conflicts with ours; the installer refuses to overwrite it.
[*]The window has no password field and no controls for the host's permissions yet; it is English only.
[*]A bug in the native module can crash the game (it aborts on an internal error).
[*]The install is command-line only; a guided installer is being built.
[/list]

[size=4][b]FAQ[/b][/size]

[spoiler]
[b]Does it work?[/b] Partly; see the status above. Playing together in two real games has not been verified yet.

[b]How do the players connect?[/b] Through Steam's peer-to-peer networking, with a relay as a fallback that is being built. By design nothing has to be set up. It is being tested: inside one game it is proven, between two different accounts it has not been tried yet.

[b]Is winhttp.dll safe? My antivirus flags it.[/b] See the security page above. Check the hash against the release notes, and report false positives; the page lists where.

[b]Windows says "Windows protected your PC".[/b] SmartScreen reacts to a new, unsigned program. More info, then Run anyway. It appears once for the installer.

[b]Is it official?[/b] No. It is an unofficial community project.

[b]Can I use it with MPFever?[/b] No; both use the winhttp.dll slot, and our installer will not overwrite another mod's file.

[b]Will it break my saves?[/b] The mod does nothing until you host or join. A session makes every game load the host's world and writes files named feverlink3-resync-(number).sav into your save folder. Back up your saves first.

[b]Can I play on my own with it installed?[/b] Yes, by design: without a session the game plays as it always does.

[b]Which game version?[/b] Build 40420 for now. After a game update the module may need an update; if the game fails to start, run feverlink3 uninstall and tell us your build.

[b]Consoles, Mac, Linux, Epic or GOG?[/b] No. The native part is a Windows DLL and the installer finds the game through Steam.

[b]Why is it not on the in-game Mod Hub or the Steam Workshop?[/b] Transport Fever 3 has no Steam Workshop, and the Mod Hub's published rules allow only the official scripting API, so a mod with a native DLL is not expected to fit. Details: [url=https://github.com/AZalshehri7/FeverLink3/blob/main/docs/WORKSHOP.md]the publishing plan[/url].

[b]How is it different from MPFever?[/b] It is a separate, fresh implementation (Rust and Lua) built on the same idea; both projects are credited below. They cannot be installed together.

[b]How do I help or report a bug?[/b] Discord azalshehri, or [url=https://github.com/AZalshehri7/FeverLink3/issues]GitHub issues[/url]. Please attach %LOCALAPPDATA%\FeverLink3\native.log and live\mod.log.
[/spoiler]
